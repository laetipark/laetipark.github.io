# 디자인 규칙

[작업 가이드](../README.md) · [저장소 소개](../../README.md)

이 문서는 UI 방향, 레이아웃, 디자인 토큰, 반응형과 접근성 규칙의 정본입니다. 컴포넌트 구조와 파일 위치는 [프론트엔드 규칙](FRONTEND.md)을 따릅니다.

## 디자인 방향

- 개발자 개인 브랜드를 소개하는 에디토리얼 포트폴리오로 구성합니다. 프로젝트, 개발 방식과 학습 기록을 자연스럽게 이어서 읽을 수 있어야 합니다.
- 첫 화면에서 이름, 소개, 연락처와 프로젝트 진입 동선을 제공합니다. 별도의 마케팅형 랜딩 페이지를 두지 않습니다.
- 라이트 모드는 아이보리 배경과 짙은 본문을 기본으로 하고 민트·라벤더·피치 계열을 제한적으로 사용합니다. 다크 모드는 같은 정보 계층을 유지합니다.
- 소개·기술·이력은 여백과 구분선으로 구분합니다. 반복되는 카드와 그림자보다 프로젝트 이미지와 제목을 강조합니다.
- 카드 반경은 8px 이하를 기본으로 하고, 카드 안에 장식용 카드를 반복 중첩하지 않습니다.
- 기간, 운영 상태, 이력과 프로젝트 설명은 기존 자료에 근거합니다. 확인되지 않은 성과 수치나 숙련도 점수를 시각 요소로 추가하지 않습니다.

## 정보 구조와 타이포그래피

- 메인 순서는 프로필 → 프로젝트 목록 → 개발 방식·학습 기록 → 사용 기술 → 학력·자격·활동 → 연락처입니다.
- 프로젝트 목록은 전체 / 웹 서비스 / 앱 / API·백엔드 / 봇 필터와 개수를 제공합니다. Brawl Tree와 Sexynogi를 대표 행으로 강조하고, 나머지 프로젝트는 간결한 카드 목록으로 보여줍니다. 필터를 선택해도 해당 분야의 대표 행이 먼저 나옵니다.
- 목록에서도 요약·핵심 구현·기술 환경을 읽을 수 있게 하고 상세 보기와 서비스·소스 링크를 구분합니다. 필터로 항목이 바뀌어도 선택 버튼의 포커스를 유지합니다.
- 학습 기록 링크는 바로 보여줍니다. 기술은 언어, 프레임워크, 데이터·인프라, 개발 도구로 묶은 텍스트 칩으로 표현합니다.
- 본문은 한국어 시스템 산세리프를 사용합니다. 코딩용 글꼴이나 과도한 굵기를 본문 전체에 적용하지 않습니다.

| 용도      | 기본 크기 | 기준                                   |
| --------- | --------- | -------------------------------------- |
| 이름      | 36px      | 짧은 프로필의 시각적 기준점            |
| 섹션 제목 | 24px      | 섹션 간 동일한 위계 유지               |
| 본문      | 16px      | 행간 1.7, 긴 문장과 한국어 줄바꿈 고려 |
| 보조 정보 | 14px      | 기간·역할·설명 등 부가 정보            |

화면 목업과 구현 결과는 [디자인 개편 기록](../design/portfolio-redesign.md)에서 확인합니다. 지속적으로 적용할 규칙은 이 문서에만 둡니다.

## 디자인 토큰

- 전역 토큰은 `src/common/styles/index.css`의 `:root`에 정의합니다.
- 라이트와 다크 모드는 같은 토큰 이름을 공유하고 `:root[data-theme='dark']`에서 값만 바꿉니다.
- 컴포넌트 CSS에 hex나 rgba 색상을 반복해서 추가하지 말고 가능한 `var(--*)` 토큰과 기존 `color-mix()` 패턴을 사용합니다.
- 새 색상 토큰이 필요하면 의미가 드러나는 이름으로 라이트와 다크 값을 함께 추가합니다.
- 간격·글자 크기·행간·콘텐츠 폭·반경은 전역 토큰을 우선 사용하고, 같은 의미의 값을 컴포넌트별로 다르게 정의하지 않습니다.

| 범주               | 우선 사용할 토큰                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| 배경               | `--page-bg`, `--page-top-bg`, `--surface-bg`, `--surface-strong-bg`, `--surface-muted-bg`, `--surface-elevated-bg` |
| 텍스트             | `--text-main`, `--text-muted`                                                                                      |
| 브랜드·강조        | `--brand`, `--brand-dark`, `--accent`, `--mark-bg`, `--mark-text`                                                  |
| 상태               | `--danger-bg`, `--danger-text`, `--success-bg`                                                                     |
| 선·오버레이·그림자 | `--border`, `--border-strong`, `--overlay-bg`, `--shadow-soft`, `--shadow-card`, `--shadow-floating`               |
| 주요 버튼          | `--button-primary-bg`, `--button-primary-hover-bg`, `--button-primary-text`                                        |

## 레이아웃과 반응형

- 본문 최대 폭은 1040px, 모바일 좌우 여백은 16px를 기본으로 합니다. 전체 폭과 여백은 `app.module.css`의 `width: min(...)`, `padding`, `gap` 패턴을 따릅니다.
- 768px 이상에서 대표 프로젝트 행은 이미지 44%·설명 56%로 구성하고, 그 미만에서는 이미지와 설명을 세로로 쌓습니다. 나머지 프로젝트 카드는 데스크톱 2열·모바일 1열로 배치합니다.
- 대표 행과 일반 카드의 이미지 영역은 16:9를 사용합니다. 프로젝트 배너를 우선 표시하고 없으면 기존 이미지를 사용합니다. `object-fit: scale-down`으로 원본이 잘리거나 왜곡·확대되지 않게 하고 바로 아래에 이미지 종류를 설명하는 캡션을 둡니다. 두 자산이 모두 없는 항목은 빈 틀이나 임의 이미지를 만들지 않고 텍스트 카드로 표시합니다.
- 상단 섹션 메뉴와 연락처는 좁은 화면에서 줄바꿈합니다. 핵심 링크를 숨기거나 가로 스크롤에 의존하지 않습니다.
- 고정 비율이나 가변 폭 요소에는 `aspect-ratio`, `min-width: 0`, `flex-wrap`, `minmax()`처럼 overflow를 막는 제약을 둡니다.
- 반응형 분기는 기존처럼 `@media (min-width: 768px)` 또는 `@media (min-width: 1024px)`를 우선 사용합니다.
- 최소 320px 너비와 데스크톱에서 텍스트, 버튼, 카드, 모달과 채팅 입력이 컨테이너 밖으로 넘치지 않게 합니다.
- 채팅처럼 화면 높이에 의존하는 UI는 주소창 변화와 내부 스크롤을 고려해 `dvh`와 `min-height: 0` 패턴을 유지합니다.

## 프로젝트 상세와 채팅

### 프로젝트 상세

- 기존 모달 진입 방식을 유지합니다. 이름·분야와 확인된 기간·상태를 먼저 보여주고, 배너·캡션 → 개요 → 상세 이미지·캡션 → 확인된 담당 역할 → 주요 기능 → 제목별 개발 이야기 → 기술 환경 → 관련 링크 순서로 구성합니다. 자료가 없는 선택 항목은 생략합니다.
- 배너와 상세 이미지가 같은 원본 경로면 이미지를 한 번만 표시합니다. 서로 다른 자산은 각각 보존하며 배너·이미지 크게 보기 링크로 원본을 열 수 있게 합니다.
- 상세 이미지도 원본을 유지합니다. 서비스 화면, 로고, ERD와 UI 목업을 구분하고 목업의 예시 데이터를 실제 운영 성과로 설명하지 않습니다.
- 모달을 열 때 내부로 포커스를 옮기고, Tab과 Shift+Tab이 모달 내부에서 순환하게 합니다. 닫은 뒤에는 열었던 버튼으로 포커스를 돌려줍니다.
- 모달이 열려 있는 동안 배경 조작과 스크롤을 막습니다. 모달은 고정 테마 버튼을 포함한 일반 UI보다 위에 표시합니다.
- 작은 화면에서 모달 본문은 세로로 스크롤할 수 있어야 하며 닫기 버튼에 계속 접근할 수 있어야 합니다.

### Chat Laetus

- 공통 글꼴·색상·버튼 스타일을 사용하고 헤더, 이용 안내, 대화, 입력기로 위계를 구분합니다.
- 입력기는 첨부 미리보기 → 메시지 입력 → 첨부·깊게 생각하기·전송 도구 → 선택 닉네임 순서로 배치합니다. 도구에는 이해할 수 있는 텍스트를 함께 제공합니다.
- 모바일 도구 행은 필요한 만큼 줄바꿈합니다. 입력기 아래에 테마 버튼용 공간을 확보하고 입력기 높이를 추측한 고정 오프셋을 사용하지 않습니다.
- 설정 누락은 방문자가 이해할 수 있는 이용 불가 안내로 표현합니다. 개발 환경 변수와 secret 이름은 개발 문서에서 안내합니다.
- 대화·응답 준비·오류 상태를 명확히 구분하되 반복 그림자를 사용하지 않습니다. 메시지의 긴 텍스트와 URL은 컨테이너 안에서 줄바꿈합니다.
- API, 입력 제한, 저장과 메시지 표시 범위는 [API 규칙](API.md)을 유지합니다.

## 아이콘과 자산

- 아이콘은 설치된 Font Awesome 패키지와 `FontAwesomeIcon`을 사용합니다.
- 일반 아이콘은 `@fortawesome/free-solid-svg-icons`, 브랜드 아이콘은 `@fortawesome/free-brands-svg-icons`에서 가져옵니다.
- 아이콘을 위해 새 패키지를 추가하지 않습니다.
- 빌드에서 관리할 이미지 자산은 `src/assets`에 두고 import해서 사용합니다.
- favicon, 404 문서와 같이 변환하지 않을 공개 자산만 `public`에 둡니다.
- 정보성 이미지에는 내용을 설명하는 `alt`를 제공하고, 장식 이미지는 스크린 리더에서 중복 안내되지 않게 처리합니다.
- 기술 이름을 표시하기 위해 외부 배지 이미지를 요청하지 않습니다. 프로젝트별 기존 자산과 공개 저장소의 원본을 보존하고 화면 비율을 왜곡하지 않습니다. 사용자가 요청한 프로젝트 소개 배너는 새로 생성할 수 있으며 기존 화면·로고·ERD를 대체하지 않습니다.
- 화면 캡처·브랜드 썸네일·앱 및 봇 로고·ERD·UI 목업을 `imageCaption`으로 구분하고, 프로젝트 배너는 `bannerCaption`으로 설명합니다. 생성 배너는 `프로젝트 소개 배너 · AI 생성`으로 표시하며 실제 서비스 화면이나 구현 증거로 제시하지 않습니다. 실제 화면이 없는 프로젝트에 가짜 화면을 만들지 않습니다.
- 원본 경로와 출처는 [프로젝트 근거 자료](../design/project-sources.md)에 연결합니다. 생성 배너의 제작일·도구·참조 자산·제작 의도·실제 출력 크기와 파일 경로는 [생성 배너 기록](../design/generated-banners.md)에 남깁니다. 카드의 16:9 영역과 `scale-down` 배치는 생성 배너에도 동일하게 적용합니다.

## 접근성과 상호작용

- 모든 버튼은 용도에 맞는 `type`을 명시합니다. 일반 버튼은 `button`, 폼 전송 버튼은 `submit`을 사용합니다.
- 아이콘만 있는 버튼과 컨트롤에는 동작을 설명하는 `aria-label`을 제공합니다.
- 테마 토글은 우측 하단 고정 위치와 현재의 라이트·다크 선택 저장 방식을 유지합니다.
- 주요 터치 컨트롤은 최소 44px의 누르기 영역을 확보합니다.
- 버튼, 링크, 입력과 textarea의 `:focus-visible` 표시가 전역 또는 해당 CSS Module에서 보이도록 합니다.
- 모달은 dialog 의미, 모달 상태와 제목 연결을 제공하고 Escape와 backdrop으로 닫을 수 있게 합니다. 네이티브 `<dialog>`를 사용하지 않는 경우 `role="dialog"`와 `aria-modal="true"`를 명시합니다.
- 비동기 상태와 오류는 시각적 표현만 두지 말고 적절한 `role`, `aria-live` 또는 연결된 레이블을 유지합니다.
- 색상만으로 상태를 구분하지 않고 텍스트나 아이콘을 함께 제공합니다.
- `prefers-reduced-motion` 설정에서는 부드러운 스크롤과 불필요한 전환 효과를 줄입니다.

## 시각 검증

- 라이트와 다크 모드에서 텍스트·경계·상태 색의 대비를 확인합니다.
- 320·390·768·1024·1440px에서 overflow와 레이아웃 변화를 확인합니다. 채팅은 짧은 화면에서도 입력과 전송에 접근할 수 있어야 합니다.
- 키보드만으로 주요 링크, 버튼, 모달과 채팅 입력에 접근할 수 있는지 확인합니다.
- 프로젝트 상세의 포커스 복귀, 긴 설명·URL, 첨부 미리보기와 오류 상태를 확인합니다.
- 프로젝트 필터의 개수·선택 상태·표시 항목, 여러 관련 링크와 `/chat` 이동, 이미지 종류별 비율·캡션을 확인합니다.
- UI 변경 폭이 크면 브라우저에서 실제 화면을 확인한 뒤 `npm run build`를 실행합니다.
